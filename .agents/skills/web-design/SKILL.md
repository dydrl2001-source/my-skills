# Web Design

Turn the user's purpose into a coherent, usable web experience. Match the requested deliverable: a design prompt stays a prompt; a code change uses the existing project. Explain decisions in the user's language.

## Establish the brief

Read existing project instructions, relevant pages, components, styles and routes before choosing a stack or inventing a service. Preserve the user's brand, font, section count, framework and dependency constraints. Reuse available context and authorization; ask only when an unresolved fact blocks a meaningful behavior or decision. State reasonable assumptions for optional missing details and continue.

Use [design-brief.md](references/design-brief.md) when a design prompt, new page or unclear visual direction needs structure. Keep its output proportional to the request. For a small change, record only the affected goal, interface and completion criteria.

Choose sections that answer the audience's actual questions and lead to the primary action. Testimonials, customer counts, awards, scarcity and performance claims need supplied or verified evidence. Omit unsupported claims, or label examples clearly in a requested prototype. A research question or an industry pattern is not a verified competitor finding.

## Design and implement

- Create a consistent hierarchy through typography, spacing, color and content density. Follow an existing design system; choose a deliberate style when none exists. Common fonts, simple grids and restrained backgrounds are valid when they serve the brand.
- Specify only useful tokens and component states. Use legible Korean fonts when appropriate, sufficient contrast, semantic controls, visible keyboard focus, responsive layouts and reduced-motion behavior. Do not add motion or packages merely to satisfy a style checklist.
- Connect the main CTA to the requested destination or existing project action. Match established loading, success, validation and error handling; avoid duplicate submissions where relevant. Identify missing service connections honestly rather than presenting a decorative button as a completed flow.
- Use supplied assets or an available image capability when images help. Keep composition and text overlays intentional. Follow the host's available tools and relevant provider guidance; this skill does not provide a browser, image service or deployment permission.

## Verify the requested result

For implementation, use [ui-checks.md](references/ui-checks.md) to select checks for the changed behavior. Inspect the rendered page when a permitted browser is available, and run relevant existing checks. Report what actually ran and any unverified visual or service behavior. Planning-only work needs a coherent brief, not an invented build result.
