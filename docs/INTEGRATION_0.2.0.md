2026-10-21, [기존 22개 분석](SKILL_AUDIT_2026-10-21.md)을 바탕으로 사용자가 통합을 승인했다. 원본 컬렉션은 보관하고, `.agents/skills/`의 다섯 스킬을 계정용 비공개 플러그인에 선택 배포한다.

| 배포 스킬 | 통합 내용 |
| --- | --- |
| `web-design` | 디자인 프롬프트의 사용자 흐름·브랜드·토큰 체계, 랜딩페이지의 콘텐츠와 행동 연결, frontend 디자인의 시각 원칙을 새 지침으로 정리 |

| `engineering-upgrades` | 기존 용어·인터페이스·리뷰 점검에 프로젝트 읽기·요청 구체화·완료 기준만 보강 |

## 달라진 사용 방식

- 웹디자인은 현재 브랜드·폰트·프로젝트·요청한 섹션 수를 따른다. 기획만 요청하면 기획을 제공한다. 구현 시 CTA를 실제 경로나 기존 서비스에 연결하고 검증 범위를 보고한다.
- 후기·사용자 수·성과·경쟁사 조사 결과를 지어내지 않는다. 가상 예시는 예시라고 표시한다. 특정 스택·폰트·마케팅 요소 개수·모션을 일괄 강제하지 않는다.
- 카드뉴스는 UTF-8 JSON 사양에서 여러 PNG와 `manifest.json`을 만든다. 카드 크기·번호·단색/이미지 배경을 선택하고 한글과 긴 무공백 문장을 줄바꿈한다. 최소 글자 크기에서도 맞지 않으면 오류로 알리며 내용을 자르지 않는다.
- 출력 폴더는 새 경로를 사용하며, 잘못된 배경이나 기존 파일을 조용히 대체하지 않는다. 폰트·측정된 글자 경계·실제 출력 크기를 manifest에 남긴다.
- 동봉 글꼴은 NanumGothic-Regular.ttf와 OFL.txt다. 렌더러는 Python 3.11+와 Pillow만 사용하며 네트워크나 자동 설치, 문구 생성 API를 호출하지 않는다. 셸·이미지 확인 도구가 있는 환경에서 PNG를 생성하고 실제로 열어 검수한다.
- 개발 요청이 짧으면 기존 코드와 서비스를 먼저 찾아 최소 변경과 완료 기준을 정한다. 새로운 로그인 시스템·CLI 반복 루프·승인 단계를 자동 추가하지 않는다.

## 선택 배포에서 제외한 항목

`skills/`, `.claude/`, `backup/`은 출처와 비교를 위한 원본 자료다. 파일을 삭제하거나 전부 자동 활성화하지 않았다. 기존 파일명·예제·누락 자산 문제를 모두 고쳤다는 뜻은 아니다.

- Codex/Claude/Cursor 반복 루프: 기존 개발 절차와 중복되고 추가 CLI·계정·세션 관리가 필요하다.
- Flutter/Next 초기화: 실제 대상 프로젝트가 생기면 버전 정책과 예제를 먼저 검증한다.
- code-changelog: 필요한 실행 파일이 빠져 있으므로 실행 가능한 도구로 배포하지 않는다.
- code-prompt-coach: 로그 범위·원문 처리·비용 추정을 정리한 뒤 선택형 회고로 검토한다.
- web-search/web-to-markdown/ChatGPT 웹 조사: 현재 연결된 도구와 환경에 맞춘 별도 작업으로 남긴다.
- workthrough 문서화 사이트와 로고 제거 예제: 기본 개발·이미지 제작에 자동으로 끼워 넣지 않는다.

## 검증과 한계

기존 카드 렌더러에서 무공백 한글 문장을 지정 폭 180px로 감쌌을 때 1,890px 줄이 생성되는 문제를 재현했다. 새 렌더러는 PNG 크기, 실제 줄 경계와 텍스트 보존, 색상 대소문자, 상대 배경 경로, 오류·덮어쓰기·리소스 제한 등을 동작 테스트로 검증한다. 세 장의 한국어 샘플을 실제로 열어 줄바꿈·대비·크롭·번호·예시 표시를 확인했다. 샘플과 개인 데이터는 저장소/플러그인에 포함하지 않는다.

웹디자인과 요청 구체화는 세 사례로 독립 점검했다: 기존 HTML/CSS·브랜드 폰트·3개 섹션·`/register` CTA 유지, 빵집의 디자인 프롬프트만 작성, 기존 인증·신청 서비스를 재사용한 버튼 추가 계획이다. 기존 지침을 읽은 평가자도 세 사례를 통과할 수 있었다. 따라서 이번 점검은 충돌하는 지침을 줄이고 적용 가능성을 확인한 것이며, 모델 성능 향상을 수치로 입증한 실험은 아니다. 실제 웹사이트를 새로 제작·배포한 검증도 아니다.

전체 테스트는 `python -m unittest discover -s tests -v`, 패키지는 `python scripts/build_plugin.py --output <저장소-밖의-ZIP>`으로 확인한다. GitHub Actions는 Windows와 Ubuntu에서 같은 테스트와 패키징을 실행한다. 개별 실행 결과는 저장소 Actions에서 확인한다.

현재 카드 레이아웃은 제목·본문을 위에서 아래로 배치한다. 임의 폰트·이모지의 글리프, 사용자가 고른 사진의 대비, 결과물의 시각 완성도는 실제 PNG에서 확인해야 한다. 이 스킬은 이미지 생성 모델·SNS 게시 서버를 제공하지 않는다. 영상 분석 역시 Python·네트워크·모델 준비 상태에 따른 실행 조건이 있다.

저장소 원본과 계정 플러그인은 별도 배포 단계다. 기존 `내 작업 도구` 플러그인 ID와 비공개 범위를 유지해 업데이트하고, 새 플러그인을 중복 생성하지 않는다.
